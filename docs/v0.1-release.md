# ragrefine v0.1 release record

## Release boundary

`ragrefine` 0.1.0 is a retriever-agnostic, post-retrieval refinement library.
It accepts one supplied candidate pool and returns reordered or selected input
candidates with an auditable trace. It does not own ingestion, indexing,
first-stage retrieval, embeddings, LLM generation, or deployment.

The release contains the core refinement API, deterministic lexical and pattern
signals, optional CrossEncoder reranking, rank fusion, deduplication, context
selection, and an optional Haystack integration. The Haystack extra packages a
document adapter, `RagRefineComponent`, prompt builder, and a frozen
in-memory retrieval fixture. Its integration tests exercise the retrieval →
refinement → prompt handoff without changing Haystack retrieval semantics.

## Evaluation and profile decisions

The [evaluation contract](evaluation-contract-v0.1.md) is the authoritative
human-readable definition of the frozen-pool comparison rules. The immutable
artifact inventory and replay procedure are in
[`benchmarks/artifacts/README.md`](../benchmarks/artifacts/README.md).
Machine-readable artifacts, rather than this release note, are the source of
truth for metrics and timings.

| Profile | Release decision | Evidence boundary |
| --- | --- | --- |
| B0 | Baseline | Frozen first-stage Top-50 order. |
| B1-reference | Retained neural profile | Exact MiniLM-L6/CUDA configuration in the evaluation contract. |
| B2-L | Retained lightweight profile | Deterministic lexical/CPU configuration in the evaluation contract. |
| B2-P | Not retained | SciFact evidence did not support retaining the pattern-only profile. |
| B3 | Not retained | Equal-weight fusion did not improve on the retained single-channel profiles. |
| B4 | Implemented, not quality-qualified | Context-efficiency behaviour requires separately scoped evidence. |

All B0–B3 comparisons reuse the same frozen first-stage candidate pool. A
candidate-pool recall value is a ceiling imposed by candidate generation, not a
refinement improvement. No profile is described as improved except for the
specific measured configuration supported by its persisted artifact.

## Final integration evidence

| Evidence | Location | What it establishes |
| --- | --- | --- |
| Core and Haystack integration tests | `tests/integration/` | Adapter, component, fixture, prompt handoff, and opt-in generator boundaries. |
| Optional dependency declaration | `pyproject.toml` (`haystack-ai==2.31.0`) | Haystack remains outside the lightweight default install. |
| CI wheel job | `.github/workflows/ci.yml` | Tests with the Haystack extra and imports the installed wheel. |
| Clean-wheel exercise | Release validation command below | A fresh virtual environment installed the built wheel with `[haystack]`, retrieved frozen documents, refined them, and built a prompt. |
| Retained artifacts | `benchmarks/artifacts/retained-v1.json` and external `retained-v1` bundle | Frozen ranking inputs, sidecars, and reproducible retained-profile analysis. |

The optional generator smoke uses an explicit OpenAI-compatible API key and
base URL supplied by the caller. It records source IDs, contexts, trace, and
responses for integration inspection only; it neither changes a benchmark nor
proves answer-quality improvement.

The release-wheel exercise is:

```powershell
uv build
uv venv C:\Temp\ragrefine-release-wheel
uv pip install --python C:\Temp\ragrefine-release-wheel\Scripts\python.exe "dist\ragrefine-0.1.0-py3-none-any.whl[haystack]"
```

The installed environment must import
`ragrefine.integrations.haystack`, retrieve from `FrozenHaystackFixture`, pass
the resulting documents to `RagRefineComponent`, and build a prompt. This
release passed that check before version promotion.

## Known limitations and closure

- Evaluation evidence is configuration- and dataset-specific; it is not a
  general claim that refinement improves every retriever or domain.
- The hard-negative v1 fixture is saturated because relevant candidates begin
  at rank 1; it is a deterministic schema diagnostic, not a profile-selection
  benchmark.
- Runtime records are deployment observations, not production service SLOs or
  pure CPU-versus-GPU comparisons when model profiles differ.
- Entity extraction, general query analysis, relevance gates, ONNX comparison,
  and production integration remain outside this release boundary.

Further production work—including Azure resources, application-specific RAG
orchestration, secrets management, operational telemetry, and deployment—must
live in a separate repository. It is intentionally outside the `ragrefine`
library and this release.
