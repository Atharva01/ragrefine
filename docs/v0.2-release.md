# ragrefine v0.2 release record

Version **0.2.0** marks the project complete for its stated purpose: building
a RAG pipeline on top of `ragrefine` and Haystack. It adds the last
integration gap (serializable refiner profiles) and the end-to-end pipeline
path, and records the evaluation state with no broader claims than the
evidence supports.

## What is in v0.2.0

- **Serializable refiner profiles** — `RagRefineComponent` now round-trips
  through `to_dict`/`from_dict` and Haystack YAML for the built-in `b0` and
  `b2-l-lexical` profiles, and custom profiles via `register_refiner_factory`.
  Previously only the no-op `b0` profile was serializable, so a pipeline with
  real refinement could not be saved or loaded.
- **Runnable RAG pipeline** — `build_rag_pipeline` wires BM25 retriever →
  `RagRefineComponent` → prompt builder → chat generator (DeepSeek,
  OpenAI-compatible), with a prompt-only mode when no key is configured.
- **Pipeline guide** — [docs/rag-pipeline-guide.md](rag-pipeline-guide.md):
  profiles, custom factories, custom stores/retrievers/generators, and the
  honest claims policy.
- **Executed Ragas A/B (RRF-97)** — retained artifacts at
  `benchmarks/results/haystack-ragas-v1/`,
  `benchmarks/results/haystack-ragas-scores-v1/`, and
  `benchmarks/results/haystack-ragas-analysis-v1/` with SHA-256 sidecars and a
  verification report (all checks pass).

## Evaluation state (source of truth: machine-readable artifacts)

| Claim | Evidence | Status |
| --- | --- | --- |
| B0 frozen baseline | SciFact 300-query snapshot | Retained |
| B1 neural reranking improves ranking | B1-reference (MiniLM-L6/CUDA) and B1-light (TinyBERT-L2/CPU) | **Retained** |
| B2-L lexical improves ranking | SciFact B2-L ablation | **Retained** |
| B2-P patterns improve ranking | SciFact B2-P ablation | Not retained |
| B3 fusion improves ranking | All B3 profiles | Not retained |
| Refinement improves end-to-end generation | Ragas A/B (RRF-97), 13 paired queries | **Inconclusive** — refined scores directionally higher on faithfulness and factual correctness, but paired bootstrap CIs include zero; no improvement claimed |

The v0.1 evaluation and regression contract
([docs/evaluation-contract-v0.1.md](evaluation-contract-v0.1.md)) continues to
govern metrics, frozen-pool rules, and artifact requirements.

## Explicitly deferred (not pipeline prerequisites)

- Entity signals, the generic query-analyzer layer, and relevance gates —
  future hypotheses per `AI_PRD.md`; not implemented in v0.1/v0.2.
- ONNX inference experiment — an inference-optimization comparison, not a
  ranking change; not required for the pipeline path.

These remain documented roadmap items and are intentionally not part of the
v0.2 completion claim.

## Known limitations

- The Ragas A/B test set is small (13 queries) and partially saturated:
  `context_precision` and `id_based_context_recall` are 1.0 in both arms.
  A discriminative follow-up set would be needed before any end-to-end
  improvement claim could be evaluated.
- `answer_relevancy` requires an explicitly pinned embedding provider
  (`RAGAS_EMBEDDING_MODEL`/`_BASE_URL`/`_API_KEY`) and is omitted otherwise.
- Refinement is post-retrieval only; `ragrefine` deliberately does not
  own ingestion, indexing, retrieval, generation, or orchestration.
